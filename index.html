The manual way

Two weeks of typing, every month

Every month the admins received about 25 workshop invoices for the company fleet, some running to many pages. Each one was typed in by hand: the invoice details, the vehicle, and every part and labour line. It took about two weeks, mistakes were hard to catch, and the data could not answer simple questions like which vehicles cost the most.

  • Mapped the existing process with the admins
  • Defined what done means: every invoice captured, checked and traceable
  • Scoped the solution end to end, from capture to dashboard

Capture

AI reads it, a person confirms it

I built an internal web app where admins upload invoice PDFs. Each page is archived first, then sent through an n8n workflow to ILMU models, which read the page and return the invoice header, the vehicle and every line item as structured rows. The app checks the result, flags anything that looks wrong, and a person confirms each invoice in a quick review queue.

  • Designed the upload, archive, read, check and review flow
  • Wrote rules for what OCR misses, like invoice numbers that run across pages and totals that do not match the lines
  • Logged every correction, so each number traces back to its page

Engineer

Clean data, in layers

Confirmed invoices flow into Microsoft Fabric through a medallion model. Bronze keeps the raw extract, silver cleans and standardises it, and gold shapes it into tidy tables for reporting and AI. Data-health checks run along the way, so the team can see how complete and verified the data is.

  • Designed the bronze, silver and gold layers
  • Mapped free-text line items to service types like tyres, brakes and battery
  • Added health measures: verified, complete, and line items that add up to the printed total
  • Microsoft Fabric
  • SQL
  • Python
  • Data modelling

Model and design

Built with AI, checked by a person

I used Claude Code with the Power BI MCP to build the semantic model and the report. The AI wrote and organised the measures, built the pages from a design template and documented the model, and every number passed a validation check before release. Six pages cover spend, vehicles, workshops, parts and labour, data health and the OCR pipeline.

  • Defined the KPIs first, each with the question it answers
  • Directed the AI build and reviewed every measure
  • Redesigned the report around one question per page

50+ measures / 6 pages / validated

Secure and share

Everyone who needs it, without a licence each

The report is published to Power BI Service and embedded in DataHub, the internal portal I built. Staff sign in with their company account and see only the dashboards they have been given, and row-level security narrows each person to the data they are allowed to see. Because DataHub uses Power BI's App Owns Data model, viewers do not need a Power BI licence.

  • Set up RLS roles and the access rules behind them
  • Embedded the report in DataHub, where admins and dashboard owners add or remove viewers
  • Tracked usage and refresh health from one admin view

Ask ILMU

Ask the data a question

I built a bridge between our data models and ILMU, so anyone viewing the dashboard can ask questions in plain language, right inside DataHub. ILMU answers from the same governed model as the report, can compare months and years, and replies with a table or a chart. Because it runs on ILMU, the data stays with us.

  • Built the connection between the semantic model and ILMU
  • Added guardrails so answers come only from approved data
  • Placed it beside the dashboard, where people already work
